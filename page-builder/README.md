# Page Builder

A local GUI for designing pages and posts for this Jekyll site without hand-writing Markdown or front matter. It runs on your machine, opens in your browser, and reads/writes the real files in this repository (`_posts/`, the static pages, `_config.yml`, `assets/img/`). Nothing is uploaded anywhere — it's just a local editor.

## Run it

```
cd page-builder
npm install
npm start
```

Then open **http://127.0.0.1:4000**.

## What it can do

- **Blog Posts** — create/edit/delete posts with a rich text editor. Handles the `_posts/YYYY-MM-DD-title.md` filename and YAML front matter (title, subtitle, tags, cover/thumbnail images, comments) for you.
- **Static Pages** — edit About Me, Networking, and Resume through the same rich text editor.
- **Homepage Intro** — edit the title, subtitle, and disclaimer text at the top of the homepage. (The post-listing section below it is generated by Jekyll and isn't editable here.)
- **Site Design & Settings** — edit `_config.yml`: site title/author/avatar, colors, navbar links, and footer social links, without touching YAML directly. Comments and unrelated settings in `_config.yml` are left alone.
- **Image uploads** — drag an image into any image field and it's saved into `assets/img/` and referenced automatically.
- **Graphics Designer** — a Canva-style canvas for composing backgrounds, shapes, text banners, and images, then flattening the result to a real PNG in `assets/img/`. Open it from the sidebar to design freely (saved graphics show up in a gallery you can reuse), or click "Design…" next to any Cover image / Thumbnail / Avatar field to open it pre-sized for that spot and have the result fill the field automatically. It composes real image assets rather than positioning elements on the live page itself, since the site's theme (Beautiful Jekyll) renders pages/posts as flowing text with a single cover image, not a freeform canvas.

## After you save

The tool writes files straight into the working tree — it does **not** commit or push. Review the change with `git diff` / `git status` in the repo root and commit it the normal way when you're happy with it. Jekyll (or GitHub Pages) will pick up the change on the next build.

## Notes

- This tool binds to `127.0.0.1` only — it's not reachable from other machines.
- `page-builder/` is excluded from the Jekyll build via `_config.yml`, so it never ships as part of the site itself.
